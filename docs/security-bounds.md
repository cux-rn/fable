# Fable-Stream 的安全界：多用户 keyed duplex × STREAM

版本：v0.3 分析（2026-09-14）。对应规范 §0"机密性/完整性 128 bit（≤ 2^64 字节/密钥）"与"μ 个用户下退化 ≤ log2(μ) bit"，以及 §8-8。

## 1. 参数与记号

| 符号 | 含义 | Fable 取值 |
|---|---|---|
| b | 置换宽度 | 512 |
| r | 速率 | 256 |
| c | 容量 | **256** |
| k | 密钥长度 | 256 |
| τ | 标签长度 | 256（默认）或 128 |
| n | AEAD nonce 长度 | **192** = 152（N_f）+ 32（ctr）+ 8（flag） |
| μ | 用户（密钥）数 | — |
| N | 攻击者的离线置换调用次数（P_12 与 P_ℓ 均计入，ℓ ∈ {8, 6}） | 目标 ≤ 2^128 |
| M | 全部用户的在线数据块总数（每块 32 字节；AD 与消息都算，每条消息另加初始化与最终化各 1 次调用） | 每用户 ≤ 2^64 字节 ⇒ ≤ 2^59 块 + 2·（消息数） |
| q_E, q_D | 加密 / 解密（验证）查询数 | — |
| F | 每用户的文件数（Fable-Stream） | — |
| L | 分块大小 | 64 KiB（默认） |

置换 P_12 / P_ℓ 建模为随机置换（理想置换模型）；两参数集通过 IV1 域分离，可视为独立实例。

## 2. Fable-AEAD：多用户 keyed duplex 界

Fable-AEAD 是标准的 keyed duplex：初始化把 (IV, K, N) 经 P_12 混合并再注入 K 到容量；随后每块 P_ℓ；最终化再注入 K 并经 P_12 取速率作标签。适用的已有结果：

- Jovanovic–Luykx–Mennink，ASIACRYPT 2014（JLM14）："Beyond 2^{c/2} security in sponge-based AE"，单用户 nonce-respecting 界；
- Daemen–Mennink–Van Assche，ASIACRYPT 2017（DMV17）：全状态 keyed duplex 的多用户界（内建多用户支持）；
- Dobraunig–Mennink 2019/2020 等对"密钥再注入到最终化"的改进只让界更好，这里不使用。

把 DMV17 的界写成与 Fable 参数对应的形式（常数与"路径重数"的精细项按最坏情况 L, Ω ≤ M 合并，见 §5 的说明），对 nonce-respecting 的加密与 q_D 次验证查询：

  Adv^{mu-AE}_{Fable-AEAD}(μ, N, M, q_D) ≤
    **[A]** μ·N / 2^k                       （多用户密钥猜测）
  + **[B]** M·N / 2^c                       （离线查询命中某个在线内部状态：状态恢复 / 伪造）
  + **[C]** M² / 2^{c+1}                    （在线状态之间的内部碰撞，生日）
  + **[D]** (M + N)² / 2^{b+1}              （宽度层面的碰撞，b = 512，可忽略）
  + **[E]** q_D / 2^τ                       （标签猜测）
  + **[F]** nonce 重复概率（由 nonce 生成方式决定，见 §3）

各项由哪个参数决定：

| 项 | 决定参数 | 数值（μ = 2^32 用户，每用户 2^64 字节 ⇒ M ≈ 2^91，N = 2^128，q_D = 2^64） |
|---|---|---|
| [A] μN/2^k | **k = 256** | 2^32·2^128/2^256 = 2^-96 |
| [B] MN/2^c | **c = 256** | 2^91·2^128/2^256 = **2^-37** |
| [C] M²/2^{c+1} | **c = 256** | 2^182/2^257 = 2^-75 |
| [D] (M+N)²/2^{b+1} | b = 512 | 2^-256 |
| [E] q_D/2^τ | **τ** | τ=256：2^-192；τ=128：2^-64 |

说明：
- 只看单用户（μ = 1，M = 2^59 块）时 [B] = 2^59·2^128/2^256 = 2^-69，[C] = 2^-139：**远优于 128 bit 目标**，这正是 c = 256 的作用——JLM14 的核心结论是 keyed duplex 的安全达到 min{2^{b/2}, 2^c, 2^k} 级而不是 2^{c/2}，所以 c = 256 在 N = 2^128 时仍有 2^-69 的余量。
- **多用户退化**：[A] 随 μ 线性增长（log2(μ) bit），[B] 随总数据量 M（即 μ × 每用户数据）线性增长，也是 log2(μ) bit；[C] 随 M² 增长，是 2·log2(μ) bit，但其基数 2^-139 极低，在 μ ≤ 2^32 时仍 ≤ 2^-75。**结论：在 μ ≤ 2^32、每用户 ≤ 2^64 字节、N ≤ 2^128 的范围内，总优势 ≤ 2^-37，多用户退化由 [A]、[B] 主导，恰为 log2(μ) bit，满足 §0 声明。** 若要把界压到 2^-128 以下，需要 N ≤ 2^{2^... }，即离线计算量 ≤ 2^37·... —— 更准确地说，[B] = MN/2^256 ≤ 2^-128 要求 M·N ≤ 2^128；在 M = 2^91 时 N ≤ 2^37。这不是弱点：§0 的"128 bit"是**攻击代价**语义（N ≈ 2^128 时优势仍 ≪ 1），与 ChaCha20-Poly1305 等的多用户界（MN/2^k 形式）同类。

## 3. nonce 长度 n = 192 决定的项 [F]

Fable-AEAD 是 nonce-based，重复 nonce 会泄露明文异或并破坏认证（§6）。nonce 由 Fable-Stream 生成：N = N_f ‖ ctr ‖ flag，其中 N_f 152 bit 随机、ctr 32 bit 递增、flag 1 bit。

- **同一文件内**：ctr 递增且 flag 区分末块 ⇒ 所有分块 nonce 互不相同（确定性），上限 2^32 块 = 256 TiB（64 KiB 分块）。
- **同一密钥的不同文件**：N_f 随机，F 个文件发生碰撞的概率 ≤ F²/2^{153}。
  - F = 2^32 文件（每文件 ≤ 2^32 字节即 2^64 字节总量）：2^64/2^153 = **2^-89**；
  - F = 2^48 文件（每文件一个 64 KiB 分块，2^64 字节总量的极端情形）：2^96/2^153 = **2^-57**。
- 多用户下 nonce 碰撞只在同一密钥内有意义（不同密钥的相同 nonce 无害），因此 [F] 不随 μ 增长。
- 若上层协议改用计数器式 N_f，[F] = 0。

**结论：[F] 由 n_f = 152 决定，在 2^64 字节/密钥的数据上限下 ≤ 2^-57（最坏文件粒度）～ 2^-89（典型）。** 这是整个界里除 [B] 外最大的项；若希望 [F] ≤ 2^-128，需要把文件数限制在 F ≤ 2^12（不现实）或改为计数器 nonce。规范应把这一条写进 §4.1 的使用说明。

## 4. STREAM（HRRV15）组合

Hoang–Reyhanitabar–Rogaway–Vizár（CRYPTO 2015）定义了在线 AE 的 nOAE 安全并证明 STREAM 构造：把消息切成分块，第 i 块用 AEAD 在 nonce (N, i, 是否末块) 下加密，AD 包含头部。其定理（Theorem 2 形式）：

  Adv^{nOAE}_{STREAM[AEAD]}(A) ≤ Adv^{nAE}_{AEAD}(B)，

其中 B 的查询数 = A 的分块总数（q_E, q_D 按分块计），且 B 是 nonce-respecting 当且仅当 A 对文件 nonce 是 nonce-respecting。归约是紧的、无损的（没有额外的乘法因子）：STREAM 的抗截断（末块 flag 必须出现）、抗重排（ctr 进 nonce）、抗跨文件拼接（N_f 进 nonce、头部进 AD）都由这一归约覆盖。

代入 §2 的界：Fable-Stream 的多用户 nOAE 优势 ≤ [A]+[B]+[C]+[D]+[E]+[F]，其中 M 按**分块总数 × 每块的置换调用数**计：每 64 KiB 分块 = 2048 个 P_ℓ + 1 个 AD 块 P_ℓ + 初始化与最终化 2 个 P_12 ≈ 2051 次调用，即 M ≈ 1.0015 × (数据块数)，与 §2 的数值无实质差别；q_D 按分块计（一次 1 GiB 文件的伪造尝试 = 2^14 次分块验证）。

## 5. 各参数的作用一览

| 参数 | 决定的项 | 若改动会怎样 |
|---|---|---|
| c = 256 | [B] MN/2^c、[C] M²/2^{c+1}、伪造/状态恢复 | c = 192（§7.2 的 320 bit 速率方向）：[B] 在 M = 2^91, N = 2^128 时变为 2^27 > 1，**多用户界失效**；即使单用户 M = 2^59 也只剩 2^-5。速率 320 只能配"数据量上限 + 单用户"的声明 |
| k = 256 | [A] μN/2^k | k = 128 会让 [A] = μ·2^-128，多用户下直接不足 |
| τ | [E] q_D/2^τ、密钥承诺（`key-commitment.md`） | 128 bit 标签：伪造 2^-64/次查询累计、承诺 64 bit；192 bit 是折中 |
| n_f = 152 | [F] 随机 nonce 碰撞 | 每密钥文件数 F 的平方 / 2^153 |
| ctr 32 bit | 文件大小上限 2^32 × L | 与安全无关，只是容量 |
| b = 512 | [D] | 可忽略 |
| ℓ（P_8 / P_6）与 P_12 | 不出现在模式层的界里 | 它们决定"理想置换假设"是否成立，由 ANALYSIS-LOG 的差分/线性/差分-线性余量论证支撑（默认集数据阶段 2.1×、初始化 3.2×） |

**关于 DMV17 精细项的说明**：DMV17 的界用"路径重数" L（攻击者知道完整输入的重复路径数）和 Ω（解密/覆写相关项）替代 M 出现在 [B] 中：L·N/2^c + Ω·N/2^c。nonce-respecting 加密下 L 只计 nonce 重复带来的路径，为 0～小常数；Ω ≤ q_D 的块数。因此实际的 [B] 远小于上面按最坏情况 L+Ω ≤ M 写的值——上表是保守界。

## 6. 结论

1. 在理想置换模型下，Fable-AEAD / Fable-Stream 的多用户界为 μN/2^256 + MN/2^256 + M²/2^257 + q_D/2^τ + F²/2^153（+ 可忽略项）。
2. **c = 256** 决定状态恢复与伪造项，使单用户在 2^64 字节、2^128 离线计算下仍有 2^-69 余量；**k = 256** 决定多用户密钥猜测项；**τ** 决定标签猜测与承诺；**n_f = 152** 决定随机 nonce 碰撞项，是实际部署中最需要注意的一项（2^-57～2^-89）。
3. 多用户退化：[A]、[B] 为 log2(μ) bit，符合 §0；[C] 为 2·log2(μ) bit 但基数极低。
4. STREAM 归约无损，Fable-Stream 的界 = 上述 AEAD 界按分块计数代入。
5. 建议写入规范：§4.1 注明随机 N_f 的碰撞概率 F²/2^153 与"计数器式 N_f 可消除该项"；§7.2 注明速率 320 会让多用户界失效，只能作为单用户、限数据量的变体。
